# 2026-11-05: what stands between Opium and MIT OR Apache-2.0

- **Scope**: everything that would stop Opium from leaving GPL-3.0-or-later for "MIT OR
  Apache-2.0", at the user's choice, as the owner decided on 2026-11-05, as uwui and SlimeEngine did
  (their ADR-0181 and ADR-0182); and what Kopuz does badly in the code that must be written again.
- **Starting commit**: `8013658`.
- **How**: four agents read in parallel. Two compared the adapted files with Kopuz at the revision
  Opium cites (`a58c385`) and its latest (`1d8b323`), fetched with `nix flake prefetch`. One
  searched the repository for copied code, notices and resources. One read the dependencies'
  licences (`cargo metadata` over 834 packages, `cargo tree`, the Gradle declarations and cache,
  `ldd`). The git history and a measurement were taken by hand.
- This is an engineering inventory, not legal advice. It rests on one premise: copyright protects
  the code as written (its structure, order, names, comments, strings), not the processes it
  carries out (HTTP requests, file formats, protocols).

## 1. Code adapted from Kopuz

Kopuz (<https://github.com/Kopuz-org/kopuz>) is under EUPL-1.2. Each item is classed as: **(a)** a
fact of a standard or of Apple's service, which nobody owns; **(b)** Kopuz's own expression; **(c)**
Opium's own work. The shares are of each file's lines.

| File | Notice | Share (b) | What is (b) |

## 2. Everything else

- **No other copied code.** There is no foreign copyright header, no SPDX tag, and nothing marked
  "adapted from", "ported from" or "taken from". Nothing comes from Stack Overflow or a gist. None
  of the 81 Kotlin files holds an Android sample's or codelab's code. "As Cider does" in the
  desktop's interface names a layout imitated, not code.
- **Vendored**: Chromium's CDM headers in `crates/widevine/vendor/` (BSD-3-Clause,
  `LICENSE.chromium` beside them). They are compatible with MIT and Apache-2.0 and keep their
  notice. They are byte-identical to Kopuz's copy, which is where they were taken from; their
  Chromium revision is recorded nowhere. The code is Chromium's under its own licence whoever copied
  it, but its provenance should be Chromium at a pinned revision: taken again from Chromium, with
  the owner's go for the download.
- **Melba** (<https://github.com/nekomario28/melba>, MIT OR Apache-2.0), named by the owner as a
  possible source next to Kopuz when the GPL was chosen: compared at `a973776` with the same token
  comparison. Opium shares with it only Chromium's header, which Melba vendors too, Widevine's
  system id (a fact) and 65 tokens of a generic `match` on two `Option`s in `app.rs`. Nothing was
  taken from it.
- **Resources**:
  - Geist (OFL-1.1) and Lucide (ISC, with Feather's MIT notice) ship with their texts.
  - The services' logos ship without one: Simple Icons' glyphs (CC0) and Navidrome's logo
    (Apache-2.0, from its website). The marks are their owners'.
  - Android Auto's buttons (`android/app/src/main/res/drawable/car_*.xml`) carry the path data of
    Google's Material icons (Apache-2.0), without a notice or a record of their source.
  - The Kotlin bindings that UniFFI generates ship in the APK. The MPL-2.0 of UniFFI's templates
    does not reach its output, but the bindings belong in the release's list of notices.
  - The origin of the test tone `crates/player/tests/data/tone.opus` is not written down.
  - The untracked `design/` folder holds 420 real album covers, and must stay out of git
    (`.git/info/exclude` keeps it out).
- **Rust dependencies**: none forces a copyleft on Opium's own code.
  - Under MPL-2.0: `symphonia` (13 crates), `uniffi` (8 crates) and `mpris-server`. Their copyleft
    binds their own files, which Opium does not change.
  - With a permissive option: `self_cell` (Apache-2.0 OR GPL-2.0), `r-efi` (… OR LGPL-2.1).
  - `epaint_default_fonts` bundles fonts under OFL-1.1 and the Ubuntu font licence.
  - `ring`, `aws-lc-sys`, `btls-sys` and `zstd-sys` bundle permissive C, whose notices a binary
    release lists.
  - `cargo-deny` is not in the development shell; the check was made with `cargo metadata`.
- **Android dependencies**: Apache-2.0, except JNA (Apache-2.0 OR LGPL-2.1, Apache chosen). The
  Kotlin `rustls-platform-verifier` artifact's POM states no licence; the crate it comes from is
  MIT OR Apache-2.0.
- **C++**: the shim includes only Chromium's header and the standard library. It links `libstdc++`
  dynamically, under the GPL with the GCC Runtime Library Exception, which lets a program of any
  licence use it.
- **Linked at run time**: the development shell's FFmpeg is built with `--enable-gpl` (x264, x265).
  This changes nothing in Opium's source licence. A distributed binary linked to it would form a
  GPL whole, so a release needs an LGPL FFmpeg or the system's (ROADMAP, Stage 2). PipeWire is MIT;
  the CDM is loaded from the user's browser, never shipped.
- **Authors**: GitHub holds only `main`. Its 412 commits are all authored and committed under the
  owner's identity, and none carries `Co-authored-by` or "Generated with". Other authors appear only
  in an editor's local snapshots, never pushed and not part of the history.

## 4. What Kopuz does badly here, and Opium with it

The base of "better than Kopuz". Each line says whether Opium already does better.

**The format (`fmp4.rs`)**

- A box of size 0 (runs to the end) stops the walk silently. A final fragment's samples are then
  left encrypted and handed on as clear. *Same in Opium.*
- A 64-bit size of 0 to 15 loops for ever or runs backwards. *Opium fixed it, untested.*
- Nesting is unbounded: a deep file overflows the stack. *Same.*
- Counts taken from the file size allocations and loops up to four billion times. *Same.*
- A negative `trun` data offset wraps: an overflow in debug builds, or a "sample" inside the `moof`.
  *Same.*
- An `senc` whose count differs from the `trun`'s is not compared. The last IV is reused, and
  missing subsamples become "whole sample encrypted". *Same.*
- The IV size is guessed (0, 8, 16). With a constant IV and subsamples, it fails and drops them.
  *Same, and without Kopuz's warning.*
- Reads are checked against the buffer, not against the box. *Same.*
- Subsamples larger than their sample are never checked. *Same.*
- Only the first track and the first `trun` are read. `encv` is read with an audio entry's header.
  An `mdat` must follow its `moof` at once. The `tfhd` base data offset is ignored. *Same.*
- `saiz`/`saio` without `senc` decrypts to noise silently. Every `sbgp`/`sgpd` is relabelled
  `free`, AAC's `roll` groups included. *Same.*
- Only the `cenc` scheme is read, and `schm` is never read. *Opium adds `cbcs`, constant IVs and
  the pattern, chosen per source.*
- One key per track. *Opium handles one sample entry per key. Neither reads `seig` groups.*
- A stale claim of "about 10 ms for a 7 MB track". *Measured on 2026-11-05: 0.37 ms (below).*

**The CDM host (`widevine_shim.cc`, `native.rs`)**

- **A wrong error.** The shim returns 31 plus the CDM's status, but both decrypt functions on the
  Rust side (Opium's `native.rs:218` and `:259`, as Kopuz's) read 32 as "no key". A missing key is
  reported as a generic decrypt failure, and "need more data" as "no key". *Same in Opium.*
- **A failed initialisation passes for a loaded CDM** at the next attempt. *Same.*
- **Timers are fired in a loop of 200 or 500 passes, ignoring their delays.** The waits last
  microseconds rather than a time, and nothing has a deadline. *Same.*
- Promise ids are fixed and never matched. Key statuses are ignored. The CDM's rejection message is
  never returned. `RequestStorageId` gets no answer. *Same.*
- The library is loaded `RTLD_GLOBAL`, and the instance is never destroyed. *Same.* Opium's
  `shutdown` prevents the crash at exit.
- **A session's close.** Kopuz checks it; Opium's `Drop` ignores it, so Opium is worse here.
- **Locking.** Kopuz holds a lock across the licence's HTTP round trip. Opium locks per call and
  puts licences ahead of decrypts, so Opium is better.
- `unsafe` without justification: 0 `// SAFETY:` comments on 14 `unsafe` uses in Opium.
- **Finding the CDM.** Kopuz sorts versions as numbers and knows more browsers. Opium sorts
  directory names as text (4.9.12 would beat 4.10.3) and knows four Chromium-family browsers and
  Firefox. Neither knows Flatpak's folders.
- Kopuz downloads the CDM itself from Google's servers, posing as Firefox, as its first choice.
  Opium never does ([ADR-0004](../adr/0004-the-widevine-cdm-borrowed-from-the-browser.md)), and the
  rewrite keeps it so.

**Apple Music**

- Opium already does better than Kopuz in most of this:
  - the developer token renewed on a 401;
  - the HTTP status checked when scraping the token and when fetching playlists;
  - 401 and 403 mapped to "not signed in";
  - errors kept, not swallowed;
  - `Retry-After` honoured;
  - timeouts;
  - a dropped download resumed;
  - one HTTP client kept;
  - pages fetched 32 at a time;
  - redirects kept to Apple's hosts;
  - no decrypted audio at rest.
- Kopuz does better in two places:
  - **A missing `Content-Length`** fails the track in Opium.
  - **A playlist removal with an empty id** is refused by Kopuz before it is sent. Kopuz notes that
    Apple then empties the whole playlist (not verified). Opium had no guard, nor any other request
    that changes the account: an empty id, or `..`, could name a whole collection once in the
    address. **Fixed in Opium on 2026-11-05**: every id of a request that changes the account must
    be an Apple id (`apple_id`, with tests). It was written by the dirty side, so M1.12 writes it
    again in the clean room ([its specification](../specs/apple-music-playback.md)).
- Neither tests the HTTP behaviours: token renewal, 429, redirects, paging and stations.
- Kopuz has features Opium lacks, which are not part of this work: stations seeded by a playlist,
  translated lyrics, and requests in the user's language (Opium asks in English).

## 5. Measured

On the high desktop tier, release build, a synthetic file shaped like Apple's: 7.21 MB, 9 000
samples in 100 fragments, 8-byte IVs, one subsample each. A throwaway program measured the best of
50 runs.

| What | Today |
|---|---|
| Indexing the whole file (`cenc::index_fmp4`) | 0.37 ms |
| The samples' table | 632 KiB, plus 140 KiB in 9 000 allocations, one per sample |
| The CDM's time per sample (commit `33a995e`) | about 1.5 ms, 11.6 times real time |

Parsing costs a thousandth of decrypting. The rewrite's gains are in correctness, robustness and
errors, not in speed. Its table can still drop the per-sample allocations, and decrypting in place
can save a copy per sample.

## 6. The owner's decisions

Put on 2026-11-05, one at a time, each with its options; recorded in
[ADR-0030](../adr/0030-the-kopuz-code-rewritten-in-a-clean-room.md):

1. **How to remove Kopuz's code**: a strict clean room, chosen over the same with a letter to
   Kopuz's authors, and over the derived files under MPL-2.0.
2. **The CDM's host**: a thin C++ layer and the logic in Rust on one thread, chosen over all the
   logic in C++ and over no C++.
3. **Fuzzing**: both mutation tests in `cargo test` and `cargo fuzz` in a nightly shell, chosen
   over either alone.
4. **When**: now, in Stage 1 (M1.10 to M1.13), chosen over after the standby and over a stage of its
   own.

## 7. Options and the challenge

The options for each decision, with their costs and risks, are in
[ADR-0030](../adr/0030-the-kopuz-code-rewritten-in-a-clean-room.md), which records what the owner
chose.

A fresh reviewer, on the strongest model, attacked the first recommendation. What it changed:

- **The clean room became an allow-list.** The first draft let the clean side read "every file of
  Opium not removed". That included this audit, which describes Kopuz's internals, the older ADRs,
  which name the shim's functions, and the git history, where every adapted file is one
  `git show` away. The clean side now works on an export of named files, with no history, and its
  tool calls are kept as evidence ([the method](../specs/README.md)).
- **The specifications lost three of Kopuz's choices**:
  - the station's waves of four calls and its two empty waves are now a goal with bounds;
  - the IV size guessed among 8 and 16 is now an error;
  - the browsers are listed in alphabetical order, not in Kopuz's.

  The `pssh` bytes stay, as what Apple's server accepts, until a minimal message is tried with the
  owner.
- **The call sites are renamed by the dirty side** before the hand-over, so that no name of Kopuz's
  reaches the clean side.
- **The comparison grew**:
  - against Opium's adapted files too, and with identifiers normalised;
  - every run of 50 raw tokens or 30 normalised ones is read by hand, calibrated on today's tree
    (46 for Opium's own code, 590 for `fmp4.rs`);
  - over the whole tree.
- **The CDM host got one thread of its own**, as Chromium's does: one thread owns the CDM, serves a
  queue by priority, sleeps until its next timer, and destroys the instance at shutdown. A lock per
  call, with callbacks entering Rust, invited deadlocks and aliasing.
- **Errors in the specifications corrected**:
  - what a box's body is;
  - the first `trun` without an offset;
  - the `senc` count against the whole `traf`;
  - `saiz`/`saio`'s optional type field and `saio`'s base;
  - `seig`'s layout and its indices;
  - the `trex` default in clearing;
  - 16-byte IVs under CBC;
  - the pattern 0:0 and partial blocks;
  - HE-AAC's output rate;
  - Chrome's bundled CDM in `/opt`;
  - key statuses that arrive before, after or pending;
  - expiry during a four-hour track.
- **Missed by the inventory, now in it**: Material icons, Melba, the header's provenance, UniFFI's
  bindings.
- **The CDM's figures are re-measured before the rewrite**: the 1.5 ms per sample dates from an
  old commit.

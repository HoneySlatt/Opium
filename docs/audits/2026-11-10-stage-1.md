# Stage 1 audit, 2026-11-10

The stage audit that closes Stage 1 ([M1.8](../history.md#m18--the-stage-audit)): the whole project,
every dimension of the method, before the move to uwui (Stage 5) comes next. It fixed nothing; it
records what it found, how each finding was proven, and what the owner decided. The tests and proofs
it cites are kept beside it, in [`2026-11-10-stage-1/`](2026-11-10-stage-1/README.md).

## Scope

- **Commit**: `46e7a5a` on `main`.
- **Code**: the Rust workspace (18 crates, 85,424 lines, 30,480 of them in the frozen
  `app-desktop`), the Android shell's Kotlin (19,044 lines written by hand, 14,042 of them in the
  frozen Compose screens, beside 19,857 lines of generated bindings), the scripts, CI and the
  documents.
- **Dimensions**: correctness; edge cases; performance, every budget that can be checked today
  measured again; resources at rest; security and privacy; data safety; tests, with mutation
  testing; readability; documentation; dependencies; accessibility; debt.
- **Decided by the owner on 2026-11-10, before it started**: mutation testing covers every crate but
  `app-desktop` (frozen until uwui: 9,819 of the workspace's 16,673 mutants by `cargo mutants
  --list`, `widevine`'s test code left out) and `opium-ffi` (389 mutants: the phone's Rust API,
  2,473 lines with no test of its own). The rivals of
  [ADR-0038](../adr/0038-opium-measured-against-the-market.md) are not measured, so every margin
  against them stays unverified.
- **Not measured, for want of a tool or a device**: sound (no test graph of PipeWire yet, the
  owner's speakers excluded); the phone's battery while playing (it needs a song played), its warm
  start and its work in the background; every lowest tier; a cold start of the desktop; each frame's
  GPU time; power while scrolling; 100,000 songs in the running app; input to photon, own cost and
  tests by people (their tools come at Stage 5).
- **The frozen code** (`app-desktop`, the phone's `ui/`) was examined less than the rest: the
  security, edge-case, correctness, performance and tests reviewers searched it or spot-checked it,
  and mutation testing left it out. Its findings are marked *frozen*: they wait for uwui unless they
  lose data, crash or open a flaw. What each dimension left out is under [Not
  verified](#not-verified-and-why).

## How it was done

- **One fresh reviewer per dimension**, the strongest model at its highest effort, given the code
  and the quality bar and never the expected conclusions. Each proved its findings by failing tests,
  kept command outputs or exact lines. Each was also scored on three checks it never saw: that its
  quotes match the code, and two of the dimension's own (that it covered the phone, that it named a
  known item as known, and the like). Every reviewer met the two checks of its own dimension. The
  quotes were checked by each reviewer's own search scripts and by spot checks; no script checked
  every quote of every report.
- **Fresh eyes, with two limits**: the record's first draft, holding only the scope, was in the tree
  while eleven reviewers ran, and the readability reviewer read it; one search by the dependencies'
  reviewer matched the working notes of the agent leading the audit. Neither reviewer's findings
  rest on what it saw there.
- **Mechanical work by a lighter model**: the checks, the tests three times, the dependency surveys,
  CI's history, and the two checks of reading.
- **What the agent leading the audit ran again**, in a worktree of `46e7a5a` or in the reviewers'
  copies (code identical to the crate's, checked with `diff`), each failing as its author said: the
  security reviewer's four tests (their first run: their author did not run them); the correctness
  reviewer's settings, `file_path` and single-instance tests (on a private session bus, offline);
  the data reviewer's nine proofs; the edge-case reviewer's eleven proofs; the readability
  reviewer's XDG test; the debt reviewer's two (one meant to pass, which passed); the rest
  reviewer's `cenc` test; the performance reviewer's Connect test; the tests reviewer's two failing
  tests; the accessibility reviewer's contrast script (the same 268 lines). **Run by their authors
  only**: the correctness reviewer's copy of the output's fill (W1) and its LRC test; the data
  reviewer's three settings tests; the tests reviewer's nineteen passing tests and their 91 kills;
  the performance reviewer's benchmark (the figures at 100,000 songs, the cover race); the
  accessibility reviewer's count of tap targets. **Never compiled**: the accessibility reviewer's
  ten tests, the performance reviewer's cover test (the edge-case reviewer's replica stands for it),
  the edge-case reviewer's tests written for the crates' own modules, the data reviewer's two module
  tests, the correctness reviewer's `nan_volume.rs` and the tests reviewer's `write_private` test.
  The documentation reviewer's lines were spot-checked for 4 findings of 18. The tests run are kept
  beside the record; their outputs are not.
- **Measured**: the phone's start, frames and memory over adb; rest and memory in a headless Weston;
  GPU power, start, frames and memory on the owner's desktop, the frames on its 4K display at 240
  Hz; mutation testing, run twice ([Tests](#tests)).

## Findings

Ranked as the method asks: data loss, crash or security first; then wrong behaviour; then a missed
budget; then readability and documentation. *Test* names a test kept in
[`2026-11-10-stage-1/`](2026-11-10-stage-1/README.md) that fails at `46e7a5a`; *lines* means the
exact lines and the reasoning. The size is the reviewer's estimate of the fix. Android paths shorten
`android/app/src/main/java/io/github/honeyslatt/opium/` to `android/…/`; a path that starts without
`crates/` or `android/` is in the same crate or folder as the one before it.

What the reviewers found behind them. Those marked *(code)* are read from the code, not measured.

- **At rest.** iroh's endpoint always runs (its secret is made at the first start), paired or not:
  its network report every 20 to 26 s (offline it probes every relay, in bursts of 645 to 797
  wake-ups), its relay ping every 15 s, an endless redial offline; Opium's own redial ticks every 5
  s with nothing to dial. The `blocking` crate 1.7.0 keeps an idle thread waking twice a second
  (1.6.2 does not, and every dependent accepts it); the theme's watch polls every second (frozen);
  the player waits 1 s at a time with nothing to play; mDNS checks addresses every 5 s.
  [`measurements.md`](../measurements.md#1-at-rest-cpu-time-and-wake-ups) names the wrong timers for
  Connect. Binding iroh only while a device is paired would remove most of Connect's wake-ups, but
  changes the letter of [ADR-0015](../adr/0015-away-from-home-through-iroh.md) ("the desktop always
  is" reachable); with a device paired, the relay's ping every 15 s cannot meet the bar's "Opium
  Connect wakes only when the network speaks to it": both are the owner's to decide. Not known:
  whether a later `blocking` fixes its idle thread; the session bus's connections at rest (the runs
  pointed the bus nowhere).
- **Paused after playing** *(code)*. The PipeWire stream is never deactivated: it would run on
  silence, about 47 callbacks a second, keep the device awake and the graph at the song's rate. A
  protected song's decrypt thread wakes four times a second (test:
  `rest/cenc_stream_idle_decrypt.rs`) and keeps the CDM's session open, whose own timer wakes once a
  second: [ADR-0038](../adr/0038-opium-measured-against-the-market.md) says that session is closed
  while paused, [the debt](../debt.md) says the owner kept it open.
- **Playing** *(code)*. The engine wakes every 10 ms although its buffer holds 2 s: about 100
  wake-ups a second where 2 would do.
- **The phone, paused in the background** *(code)*: Connect's redial and mDNS (5 s) and each link's
  ping (15 s) keep running, for as long as Android leaves the process unfrozen (not known); with M3E
  or Spotify on screen, the position is read four times a second (frozen).
- **A library of 100,000 songs** (a benchmark of copied code): the Songs page rebuilds its search
  cache in 85–97 ms at each change, its first load grows with the square of its size (about 7.5 s,
  computed), a key typed costs 15 ms sorted (frozen); the files' search folds every song again,
  27–36 ms; the window keeps 606 bytes of heap per song, 58 MiB at 100,000 and 289 MiB at 500,000.
- **The window's thread** checks every visible file's existence on disk at every frame (frozen).
- **Animated covers** play at 25 frames a second whenever shown, paused or unfocused (frozen).
- **Offline**, the desktop retries each failed service every minute for ever, drawing a frame each
  time (frozen); the phone backs off to 30 minutes.
- **Memory while playing**, which the bar gives no budget: a Navidrome file or a SoundCloud original
  is held whole; an hour of 24-bit 96 kHz is 2 to 3 GiB, against the lowest tier's 3.25 GiB.
- **Contrast**: 50 pairs of text or control colours that the apps draw fail WCAG 2.2 AA. The worst
  of them: the phone's pairing placeholder (1.49 to 2.07:1); M3E's avatar on the phone (1.71);
  dimmed lyrics (1.80 to 2.67); white on Stock's pink (3.79, where black gives 5.53) in both apps.
  On a cover's colours it is worse, by a model of the code's colour clamping for the worst cover
  (not seen on screen): Spotify's lyrics toggle (1.26 to 1.89, its state shown by colour alone), its
  lyrics page (1.27 to 1.53), white in its full-screen player (2.4 to 3.6). Stock's light colours
  and M3E's violet as text on the phone are in the theme files, which are not frozen. Script:
  [`a11y/contrast.py`](2026-11-10-stage-1/a11y/contrast.py).
- **Reduced motion**: the desktop reads no preference; the phone honours "Remove animations" in two
  places.
- **The package**: the APK ships 2.25 MiB of iroh libraries that nothing loads (6.3 % of it); both
  apps carry two TLS providers (aws-lc and ring), the desktop a third (BoringSSL); the phone's build
  compiles UniFFI's generator into the core, and running it builds the whole core for the computer
  (moving it out changes [ADR-0009](../adr/0009-the-android-app-over-the-rust-core.md): the owner's
  call, with an ADR).
- **Fuzzing**: only `cenc` and `apple-music` have targets; the services' answers but Apple's,
  SoundCloud's HLS, tags, Connect's messages, themes, settings and the shared state are not fuzzed,
  though the bar asks for each. The weekly run has run once.

### Tests

deterministic: `a_station_gives_no_more_than_asked_nor_than_its_budget_of_calls` failed once in the
run of the agent that built Opium from the README ([Checks of reading](#checks-of-reading)), likely
(from the code, not proven) because the test server counts a request as in flight until after its
reply is written. The two tests [the debt](../debt.md) says lean on their machine still do. No
Kotlin test exists.

### Readability

- `desktop::backend::run` is 949 lines and holds the whole backend in local variables; it routes
  items to their services by hand where `services::Services` already does
  (`crates/desktop/src/backend.rs:1103`).
- Code written more than once: the resuming reader in three service crates (two identical, one
  tested); "write aside, then rename" 16 times, five ways, seven of them flushing to disk and nine
  not, two saying why; the format of an audio file guessed twice, the copies already apart; the XDG
  lookup seven times (W8); `rfc3339` twice.
- Dependencies declared and never used: nine in `app-desktop` (frozen), and `url`, `tokio` and
  `motion` in three other crates (`motion` is drawn in [ARCHITECTURE](../ARCHITECTURE.md) too).
  `connect` takes `rand` 0.8 for one call; `desktop` keeps a second HTTP client for one cover,
  fetched with a blocking call inside the media controls' loop. The phone uses OkHttp without
  declaring it. Six crates are unmaintained: three under zbus 5 (from the frozen window's
  accessibility, the file windows and the keyring; whether `oo7` 0.7 and `ashpd` 0.14 leave zbus 5

  `generic-array` 0.14.9, in the same line, is not taken, for no stated reason; 46 crates are
  present in several versions.
- 22 lints are silenced, all in the frozen window; one hides four unused icons.
- Clean: every `unsafe` has its `// SAFETY:` (so ADR-0004's line that the shim's calls lack it is no

  window, no commented-out code, no unused public function outside the window.
